## 2. Vercel Edge Function Routing

### 2.1 Filesystem-Based Resolution

Vercel maps URL paths to filesystem routes automatically:

- `GET /api/aviation/v1/list-airport-delays` → `api/aviation/v1/[rpc].ts` (dynamic segment)
- `GET /api/health` → `api/health.js` (static file)
- `GET /api/mcp` → `api/mcp.ts` (static file)

### 2.2 Dynamic Route Precedence

Vercel resolves **more-specific routes first**, then dynamic catch-alls. The `[rpc].ts` pattern has higher precedence than `[...notfound].ts`:

```
Concrete files (health.js, mcp.ts, etc.)
  → Nested dynamic gateways (api/<domain>/v1/[rpc].ts, api/v2/<domain>/[rpc].ts)
    → Root-level catch-all (api/[...notfound].ts) ← LOWEST priority
```

**`api/[...notfound].ts`** (20 lines):
- Serves structured JSON 404 via `api/not-found.ts`
- Was added to replace a `vercel.json` rewrite (`#4698`) that shadowed all `[rpc].ts` gateways
- Key: Vercel `afterFiles` rewrites run BEFORE filesystem dynamic routes, so rewrites could shadow gateway files. A filesystem catch-all runs AFTER all more-specific routes.

Source: `api/[...notfound].ts:1-20`

### 2.3 vercel.json Rewrites

The `/tmp/worldmonitor/vercel.json:36-63` maps several non-`/api` URL paths to API endpoints:

| Source Path | Destination |

`/tmp/worldmonitor/middleware.ts` (363 lines) runs before any API handler. It:

- Has an exemption list (`PUBLIC_API_PATHS`) for public endpoints (health, version, product-catalog, etc.)

Source: `middleware.ts:1-46`

## 3. Domain Gateway Architecture

### 3.1 The Three-File Pattern

Each domain gateway involves exactly three files:

```
api/<domain>/v1/[rpc].ts                    ← Vercel Edge Function entry point
  ↓ imports createDomainGateway
server/gateway.ts                           ← Shared gateway pipeline
  ↓ imports create<Domain>ServiceRoutes
src/generated/server/worldmonitor/<domain>/v1/service_server.ts  ← Generated route descriptors
  ↓ imports <domain>Handler
server/worldmonitor/<domain>/v1/handler.ts  ← Domain business logic
  ↓ imports per-RPC implementation
server/worldmonitor/<domain>/v1/<rpc>.ts    ← Individual RPC handler
```

### 3.2 Entry Point (`api/<domain>/v1/[rpc].ts`)

Every domain gateway file is structurally identical (9 lines):

```typescript
export const config = { runtime: 'edge' };

import { createDomainGateway, serverOptions } from '../../../server/gateway';
import { create<Domain>ServiceRoutes } from '../../../src/generated/server/worldmonitor/<domain>/v1/service_server';
import { <domain>Handler } from '../../../server/worldmonitor/<domain>/v1/handler';

export default createDomainGateway(
  create<Domain>ServiceRoutes(<domain>Handler, serverOptions),
);
```

Source: `api/aviation/v1/[rpc].ts:1-9`, `api/conflict/v1/[rpc].ts:1-9`, `api/health/v1/[rpc].ts:1-9`

The `esbuild` bundler produces a self-contained deployed artifact; at runtime the server modules are already inlined.

### 3.3 Generated Route Descriptors (`service_server.ts`)

Located in `src/generated/server/worldmonitor/<domain>/v1/service_server.ts`. Generated by `protoc-gen-ts-server` from `.proto` definitions.

Each file exports:
- **TypeScript request/response interfaces** for every RPC
- **ServiceHandler interface** — contract the domain handler must implement
- **`create<Domain>ServiceRoutes(handler, options)`** — returns `RouteDescriptor[]`

Each `RouteDescriptor`:
- `method`: `"GET"` or `"POST"`
- `path`: e.g., `"/api/aviation/v1/list-airport-delays"`
- `handler`: async function that parses query params → calls `handler.<rpc>(ctx, body)` → returns JSON Response

Source: `src/generated/server/worldmonitor/aviation/v1/service_server.ts:405-459`

### 3.4 Domain Handler (`server/worldmonitor/<domain>/v1/handler.ts`)

Implements the generated `ServiceHandler` interface by importing per-RPC implementation files:

```typescript
import type { ConflictServiceHandler } from '../../../../src/generated/server/worldmonitor/conflict/v1/service_server';
import { listAcledEvents } from './list-acled-events';
import { listUcdpEvents } from './list-ucdp-events';
// ...

  listAcledEvents,
  listUcdpEvents,
```

Source: `server/worldmonitor/aviation/v1/handler.ts:1-27`, `server/worldmonitor/conflict/v1/handler.ts:1-32`

## 4. The Gateway Pipeline (`createDomainGateway`)

**Location**: `server/gateway.ts:692-2007` (1315 lines in the function body)

`createDomainGateway(routes: RouteDescriptor[])` returns `(req: Request, ctx?: GatewayCtx) => Promise<Response>`.

The pipeline applies these layers in order:

### 4.1 Origin Check
- `isDisallowedOrigin(request)` → 403 if origin not allowed (`gateway.ts:807-813`)

### 4.2 CORS Headers
- `getCorsHeaders(request)` → per-origin CORS headers (`gateway.ts:819-842`)
- Fails closed (500) on CORS generation errors — does NOT fall back to wildcard

### 4.3 OPTIONS Preflight
- Returns 204 with CORS headers (`gateway.ts:845-848`)

### 4.4 Defense-in-Depth: Trust Marker Stripping
- Strips `x-wm-mcp-internal-verified` and `x-user-id` from inbound request headers (`gateway.ts:866-926`)
- The gateway is the ONLY layer permitted to set these markers
- Caps buffered body at 256 KB (`MAX_INTERNAL_MCP_BODY`)

### 4.5 Internal-MCP HMAC Verification
- Present when `X-WM-MCP-Signature` header exists (`gateway.ts:947-1106`)
- Verifies HMAC signature, timestamp window, nonce replay protection
- Re-checks entitlement (tier ≥ 1 + mcpAccess)
- On success: injects trusted markers, sets `internalMcpVerified = true`
- Verified path **skips** API key validation, IP rate limiting, and enterprise auth gates

### 4.6 Session Resolution (Clerk JWT)
- Only runs for tier-gated routes, direct-LLM-quota routes, or Pro-fresh paths (`gateway.ts:1139-1150`)
- `resolveClerkSession(request)` → `{ userId, role, orgId }`

### 4.7 API Key Validation
- `validateApiKey(request, { forceKey })` — validates `X-WorldMonitor-Key` / `X-Api-Key` / cookie (`gateway.ts:1161-1165`)
- User API keys (`wm_` prefix): Convex-backed hash lookup (`gateway.ts:1179-1225`)
- Clerk session override: authenticated users bypass API key requirement (`gateway.ts:1231-1238`)
- Enterprise keys: `kind === 'enterprise'` from `WORLDMONITOR_VALID_KEYS` (`gateway.ts:1245-1247`)

### 4.8 User API Key Active-Subscription Gate (#4611)
- `wm_` user keys must map to an active subscription with `apiAccess === true` (`gateway.ts:1273-1330`)
- Fails closed (503) when entitlement backend is unavailable

### 4.9 Pro Freshness Cache Access
- Active subscribers get `live-browser` cache tier for market data (`gateway.ts:1339-1350`)

### 4.10 Legacy Pro Bearer Gate
- For `PREMIUM_RPC_PATHS` endpoints: validates Bearer token + checks Dodo entitlement (`gateway.ts:1352-1414`)
- Accepts either Clerk `role === 'pro'` OR Convex entitlement `tier >= 1`

### 4.11 Entitlement Check
- `checkEntitlementDetailed(sessionUserId, pathname, ...)` for tier-gated endpoints (`gateway.ts:1426-1491`)
- Enterprise auth and internal-MCP-verified bypass
- Special handling for `summarize-article` endpoint (principal-scoped rate limit for active subscribers)

### 4.12 Route Matching
- `router.match(request)` — O(1) static Map lookup, then linear dynamic scan (`gateway.ts:1494`)
- If POST doesn't match: POST→GET conversion for stale clients (`gateway.ts:1495-1536`)
- Cap: 1 MB body, 200 array values per key

Source: `server/router.ts:29-108`

### 4.13 Idempotency
- Opt-in for POST requests with `Idempotency-Key` header (`gateway.ts:1561-1807`)
- Scoped by principal (auth_kind + identity)
- Pre-rate-limit peek for replay; post-execution store

### 4.14 Rate Limiting (Three-Phase)
1. **Endpoint-specific** via `checkEndpointRateLimit()` (`gateway.ts:1602-1615`)
2. **Per-account API rate limit** (#3199): burst + daily meter for user keys and enterprise keys (`gateway.ts:1627-1747`)
3. **Global per-IP fallback** via `checkRateLimit()` (`gateway.ts:1749-1760`)

Internal-MCP verified path skips all IP rate limiting.

### 4.15 Direct LLM Quota
- `reserveDirectLlmQuota()` for LLM-spend endpoints (classify-event, summarize-article, etc.) (`gateway.ts:1763-1778`)

### 4.16 Handler Execution
- Runs matched handler wrapped in `runWithUsageScope()` (`gateway.ts:1814-1833`)
- Top-level error boundary: 500 on unhandled errors

### 4.17 Cache Headers + ETag
- For GET 200 responses: reads body once, applies cache tier from `RPC_CACHE_TIER` map (`gateway.ts:1862-1963`)
- Premium/auth paths get `slow-browser` tier
- ETag via FNV-1a hash + 304 Not Modified
- JMESPath projection applied before ETag hash (`gateway.ts:1916-1938`)
- Vercel CDN caching gated on trusted origin (`gateway.ts:1889-1895`)

### 4.18 Cache Tiers

Defined at `server/gateway.ts:143-168`:

| Tier | Browser max-age | Edge s-maxage | Use Case |
|------|----------------|---------------|----------|
| `fast` | 60s | 300s | Live events, flight status |
| `medium` | 120s | 600s | Market quotes, stock analysis |
| `slow` | 300s | 1800s | ACLED events, cyber threats |
| `slow-browser` | 300s | (private) | Premium/auth endpoints |
| `live-browser` | 30s | (private) | Pro-fresh market data |
| `static` | 600s | 3600s | Reference data, summaries |
| `daily` | 3600s | 14400s | Static reference, minerals |

## 6. Router Implementation

**Location**: `server/router.ts` (108 lines)

The router uses a **two-tier matching strategy**:

1. **Static routes**: O(1) `Map<string, handler>` lookup by `"method pathname"` key (`router.ts:44-45, 60-62`)
2. **Dynamic routes**: Linear scan with segment-based pattern matching for `{param}` paths (`router.ts:35-42, 65-76`)

Key details:
- Normalizes trailing slashes (`router.ts:51-53`)
- `allowedMethods()` returns valid HTTP methods for a path, auto-adding `HEAD` when `GET` exists (`router.ts:81-106`)

## 10. Key Architectural Decisions

### 10.1 Per-Domain Bundling
> "Splitting domains into separate edge functions means Vercel bundles only the code for one domain per function, cutting cold-start cost by ~20×."

Source: `server/gateway.ts:7-9`

### 10.2 Proto-First Contract
All new JSON data APIs MUST use the sebuf proto → `buf generate` → handler pipeline. Non-proto endpoints are exceptions listed in `api/api-route-exceptions.json` and enforced by `npm run lint:api-contract`.

Source: `api/api-route-exceptions.json:2`

### 10.3 esbuild Bundling
Edge functions are bundled per-file. The pre-push esbuild bundle check (`tests/edge-functions.test.mjs`) ensures deployed functions don't pull in unrelated modules.

### 10.4 Fail-Closed Philosophy
- CORS errors: 500 (not wildcard fallback) — `gateway.ts:815-842`
- Entitlement unavailable: 503 (not fail-open) — `gateway.ts:1296-1315`
- Rate limit Redis unavailable: 503 degraded mode
- User API key validation guard: 600/min per-IP cap protecting Convex backend — `gateway.ts:1187-1202`

### 10.5 Usage Telemetry
Every request through the gateway emits a usage event via `ctx.waitUntil()`, recording: requestId, domain, route, method, status, duration, auth kind, tier, plan, country, IP region, execution region, cache tier, etc.

Source: `server/gateway.ts:760-803`, `server/_shared/usage.ts`
